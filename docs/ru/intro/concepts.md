# Концепции

Короткий глоссарий терминов, используемых по всему сайту, в порядке, в
котором вы обычно их встречаете.

**Property**
&nbsp;&nbsp;Закон о вашем коде, выраженный тест-методом под `#[Property]`:
«для любого входа такой формы это утверждение верно». См.
[Быстрый старт](/ru/intro/getting-started).

**Generator / arbitrary**
&nbsp;&nbsp;Нечто, умеющее производить случайные значения заданной формы и
минимизировать их. `Gen::intBetween(0, 100)` — генератор; возвращаемый им
объект реализует
[`ArbitraryInterface`](https://github.com/rasuvaeff/property-testing/blob/master/src/ArbitraryInterface.php).
См. [Генераторы](/ru/generators/index).

**Run (прогон)**
&nbsp;&nbsp;Одно выполнение тела property с одним набором сгенерированных
аргументов. `#[Property(runs: 200)]` запрашивает 200 **успешных** прогонов —
про то, что не считается, см. «discard» ниже.

**Discard (отброс)**
&nbsp;&nbsp;Прогон, отброшенный через
[`Assume::that(false)`](/ru/controlling-runs/assume-vs-filter), потому что
precondition не выполнилась. Отброшенные попытки не расходуют `runs`; они повторяются,
пока не превышен `maxDiscards`.

**Seed**
&nbsp;&nbsp;Целое число, детерминированно управляющее random-фазой property.
Два прогона с одним seed генерируют идентичную последовательность значений —
именно это делает сообщённое падение воспроизводимым:
`#[Property(seed: 7382910)]`.

**Falsify (фальсифицировать)**
&nbsp;&nbsp;То, что происходит, когда сгенерированный (или явный) вход
ломает утверждение property. Раннер перехватывает падение и передаёт вход
shrinker'у.

**Shrink / shrinking**
&nbsp;&nbsp;Минимизация фальсифицирующего входа спуском по дереву меньших
кандидатов значения в поисках простейшего, который всё ещё падает. См.
[Shrinking](/ru/shrinking) — как строится само дерево и почему гарантированно
завершается.

**Counterexample**
&nbsp;&nbsp;Шринкнутый (минимальный) вход, фальсифицировавший property, плюс
исходный вход, падение и статистика прогонов/shrink-шагов — несёт
[`CounterExample`](/ru/api/index#counterexample), сообщается внутри
[`PropertyViolationException`](/ru/api/exceptions).

**Classify / coverage**
&nbsp;&nbsp;Запись, каким «видом» входа оказался каждый прогон (`even`,
`empty`, `boundary`, …), чтобы проверить, что генераторы реально достигают
интересных кейсов, а не проходят впустую. См. [Распределение](/ru/distribution).

**Regression corpus (корпус регрессий)**
&nbsp;&nbsp;Опциональная персистентная память (`PROPERTY_DB`) прошлых
падений, реплеящаяся перед random-фазой на каждом прогоне, чтобы
исправленный баг не мог незаметно вернуться. См.
[Корпус регрессий](/ru/regression-corpus).

**Command / state machine**
&nbsp;&nbsp;Терминология для тестирования *последовательности* операций, а
не одиночного входа — сгенерированный список `Command`, прогоняемый и против
реальной системы, и против упрощённой модели в памяти. См.
[State machine: концепции](/ru/state-machine/concepts).
